Toyheart / Technical & Aesthetic Plan

Procedural Tritone Shaders & Zero-Bloat Canvas

A minimal, dependency-free architecture for rendering real-time procedural shaders, brush-stroke textures, and future 2D/3D/video experiments before adding any application logic.

1. Stack & Philosophy (Zero Bloat)

No frameworks, no bundlers, no node_modules. Everything runs directly in the browser using native web platform APIs:

  • HTML5 + CSS3 — Minimal viewport shell (100vw × 100vh canvas) with a discreet floating control bar to switch studies and tweak parameters.
  • Vanilla ES Modules (<script type="module">) — Clean separation of engine code and shader code without needing Webpack or Vite.
  • WebGL2 + GLSL (Fragment Shaders) — GPU-accelerated pixel/procedural generation at 60fps. Ideal for noise fields, gradients, brush-stroke distortion, and fluid/paint bleed.
  • Future-Ready Hooks — The same canvas/module setup can later ingest <video> elements as WebGL textures (texImage2D) or drop in Three.js via a single CDN import map if 3D meshes are needed.

2. Core Procedural Toolkit

Both visual studies share a small set of GPU building blocks written in GLSL:

  • Fullscreen Quad Pipeline — A tiny WebGL2 wrapper (~100 lines) passing u_time, u_resolution, u_mouse, and u_seed into fragment shaders.
  • Ping-Pong Framebuffers (FBOs) — Two alternating off-screen textures so frames can feed back into themselves. Essential for paint accumulation, pigment diffusion, and motion trails.
  • Noise & Domain Warping — Simplex/value noise + Fractal Brownian Motion (fBm), where noise distorts the coordinates of other noise to create organic, sweeping brush-like curves.
  • Anisotropic (Stretched) Noise — Scaling UV coordinates along a flow direction to simulate bristle streaks and directional brush-stroke color diffs.
  • Tritone & Paper Substrate — Mapping continuous grayscale/gradient values onto a curated black / grey / white palette with subtle procedural paper fiber grain.

3. The Two Initial Visual Studies

Study A — Organic / Accumulative

Watercolour & Sumi-e on Paper

Feel: Slow, meditative, tactile. Black and grey washes bloom onto a textured paper/canvas background.

  • Paper grain: High-frequency procedural fiber heightmap that modulates where pigment settles.
  • Brush strokes: Moving ink emitters along curved noise paths with directional bristle streaks.
  • Wet-edge effect: Darker pigment pooling along the outer boundary of each wash via FBO feedback/diffusion.
Study B — Kinetic / Editorial

Runway Zebra Noise Gradient

Feel: Fast, rhythmic, high-fashion projection. Flowing tritone bands that morph like a living gradient.

  • Contour isolines: Domain-warped sine/noise waves creating organic zebra-print ribbons.
  • Brush-stroke diffs: Fast-moving anisotropic noise perturbing the edges between black, grey, and white bands so transitions feel painted rather than vector-clean.
  • Gradient drift: Global tonal gradient sweeping across the frame, shifting the density of black vs. white over time.

Note on running locally: Because ES modules require HTTP, we can serve the folder with a one-liner like python -m http.server (or VS Code Live Server), or keep shaders as JS template strings so everything stays cleanly modular.

5. Locked-In Decisions & Roadmap

  1. Dynamic Palettes: Support swapping between Cream, Warm Archival Paper, and Gallery White live in the WebGUI via tritone color uniforms.
  2. Motion Mode: Autonomous ambient generation for now; cursor/scroll interactivity will be added in a later pass by wiring u_mouse / u_scroll into the shader uniforms.
  3. Build Order:
    • Phase 1 (Now): Minimal WebGL2 engine + abstracted shader registry + WebGUI + Study B (Runway Zebra Noise Gradient).
    • Phase 2 (Next): Ping-pong FBO support in the engine + Study A (Watercolour & Sumi-e on Paper).
    • Phase 3 (Future): Cursor/scroll interactivity, <video> texture input, or Three.js 3D layer.

9. Domain Architecture — Routing, Reverse Proxy & Private Infra

As toyheart grows into a personal multi-service domain, keep toyheartlab as a pure static client app (zero server CPU, minimal egress) and route independent repositories behind a reverse proxy. 

# Multi-Repo Topology
toyheart-site/      # Static root landing page (SEO, OpenGraph previews, links)
toyheartlab/        # This repo — static WebGL Lab, Sandbox & Toybox (zero backend)
toyheart-archive/   # Peer-hosted Drive UI + Go/Rust Home-PC NAS agent + signaling API
toyheart-infra/     # Private repo — Caddyfile, docker-compose.yml, Forward Auth, TURN
Routing & Reverse Proxy

Caddy / Nginx Subdomain Map

  • toyheart.domain → Static portal (toyheart-site) for SEO & link previews.
  • studio.toyheart.domain (or /studio/) → toyheartlab served as cached static files (Cloudflare Pages or Caddy file_server).
  • archive.toyheart.domain → Peer Drive web UI + WebSocket signaling endpoint.
  • private.toyheart.domain → Personal tools & admin dashboards.
Auth & Containers

Public vs. Private & Deployment

  • Proxy-Level Auth: Use Forward Auth (Authelia, Authentik, or Cloudflare Access) or a shared .toyheart.domain HttpOnly cookie so public tools stay frictionless while private routes are blocked before reaching apps.
  • Container Strategy: Never containerize static sites (toyheartlab, toyheart-site). Use plain systemd for 1–2 Go/Rust binaries, or a single-VPS Docker Compose stack in toyheart-infra once running 3+ services (Caddy, Authelia, Archive signaling, coturn, DB).

10. Project Archive — Peer-Hosted Cloud Drive & Home-PC NAS

A lightweight Drive-style web interface where users host files from their own PCs via a small local agent, transferring data directly peer-to-peer so the VPS stores no bulk files and pays minimal egress.

System Components

Control Plane + Local Agent + Browser

  • VPS Control Plane: Handles accounts/auth, directory metadata, share links, and WebRTC signaling only.
  • Home-PC Agent (Go / Rust): Runs in the system tray, watches a chosen folder, hashes files into content-addressed SHA-256 chunks (1–4 MB), and maintains an outbound WebSocket to the VPS (no router port-forwarding required).
  • Browser P2P Transfer: Opening a share link establishes encrypted WebRTC DataChannels directly to the host PC (and any additional peers seeding chunks).
Logistics & Edge Cases

Engineering Considerations

  • NAT Traversal: STUN handles ~80% of direct connections; include a small coturn TURN relay container for strict corporate/mobile NATs (or Tailscale/WireGuard for private-only circles).
  • Large File Downloads: Stream incoming WebRTC chunks straight to disk with the File System Access API (showSaveFilePicker + createWritable) so multi-GB downloads don't exhaust browser RAM.
  • Peer Availability: Display live host/seed online status in the web UI when a home PC is asleep or offline.
